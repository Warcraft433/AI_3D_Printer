> [!IMPORTANT]
> **The 3D generation is a confirmed demo fallback.** The `error_detail` field explicitly states:
> `[DEMO FALLBACK] Generated static demo mesh (cube). Python Shap-E 3D generative inference was not executed.`
>
> **Why:** Shap-E requires PyTorch (`torch`) and GPU/CPU inference pipeline. The Python AI microservice does not have `torch` installed (`ModuleNotFoundError: No module named 'torch'` seen in model id=4). The fallback generates a valid 6-face cube OBJ and saves it to disk.
>
> **What this means:** The generation API, persistence, file storage, and frontend WebSocket response chain all work correctly. The generated mesh is not a chess-specific shape — it is a plain cube with the prompt recorded as metadata.

## 7. Known Gaps and Blockers

| Item | Severity | Description |
|------|----------|-------------|
| Shap-E / PyTorch not installed | 🔴 High | All 3D model generation is demo fallback. Real chess-specific mesh generation requires `pip install torch shap-e` in the AI venv. |
| No slicer binary | 🔴 High | G-code is a static demo file. Real slicing (OBJ → G-code) requires PrusaSlicer, Slic3r, or CuraEngine installed and invoked. |
| WebSocket library missing | 🟡 Medium | `uvicorn[standard]` or `websockets` not installed. Live WebSocket inference stream may degrade. |
| Admin login flow | 🟡 Medium | Direct admin/password login via form does not always redirect. Registration flow works. |
| OctoPrint not running | 🟡 Medium | `start-print` returns 503. Required for hardware-confirmed print start. |

## 8. What Is Working End-to-End

```
React UI  →  POST /api/generate/text/  →  Spring Boot  →  Demo OBJ written to disk
          →  Model persisted in Supabase (id=9, id=10)
          →  WebSocket event published
          →  POST /api/print-jobs  →  Print job created (id=4, id=5, status=ready_to_print)
          →  GET /api/print-jobs/{id}/download-gcode  →  G-code served (demo)
          →  YOLOv8 inference active on port 8001
          →  Error logs stored in Supabase
```
